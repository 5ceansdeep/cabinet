# 추천 설계 — 뜻(태그·가사) + 분위기(소리 숫자)

2026-09-28 정리. 지금 추천은 낱말 사전으로 요청문을 태그로 바꾸고 Last.fm 태그와 코사인 한 번 잰다.
문제와 바꿀 구조, 순서를 적는다.

## 1. 지금 문제

- **요청 해석이 낱말 사전.** 사전에 없는 말은 전부 기본값(`korean · indie · mellow`)으로 떨어진다.
  "안녕하세요"와 "집에 가고싶어요"가 같은 결과를 낸다.
- **한국 곡은 태그가 얕다.** Last.fm 에 분위기 태그가 거의 없고, 없으면 iTunes 장르("K-Pop" 하나)로 채워 곡끼리 점수가 같다.
- **곡 이름 표기가 섞였다.** iTunes 가 날에 따라 영문 가수명·번역 제목을 준다.
  가수는 MusicBrainz 로 맞췄다(9/28, `catalog/musicbrainz.ts`). 제목(잔나비 "A Thought on an Autumn Night")은 아직.

곡 DB 는 9/28 부터 원격 Postgres(Neon) — 아래 칸 추가(소리 숫자 등)는 `prisma migrate dev` 로 모든 PC 에 같이 반영된다.

## 2. 큰 플랫폼은 어떻게 하나 (공개된 일반론)

스포티파이의 재료는 넷: ① 사용자 재생목록(이름 붙은 묶음에 같이 담긴 곡 — 가장 큼) ② 듣는 행동(건너뛰기·반복·시간대)
③ 소리 분석(오디오 임베딩) ④ 웹 글·가사. 요즘 "AI 재생목록"은 LLM 이 요청문을 해석해 곡 임베딩에서 가까운 곡을 찾는 구조로 알려져 있다.

우리는 ①② 행동 데이터가 없다 → **곡 자체 정보로 추천(콘텐츠 기반)**. ③④ 를 작게 만든다.
사용자가 쌓이면 서랍에 같이 담긴 곡·던진 곡(`ShelfTrack`, thrown)이 우리만의 ①② 가 된다 — 다음 단계.

## 3. 재료

| 재료 | 출처 | 맡는 것 | 비교 |
|---|---|---|---|
| 태그 | Last.fm (없으면 iTunes 장르) | 장르·사람들이 붙인 딱지 | 코사인 |
| 가사 → 주제 태그 | LRCLIB + GPT | 뜻 (이별·귀가·위로·그리움) | 코사인 |
| 소리 숫자 | ReccoBeats | 분위기 (에너지·밝기·춤·어쿠스틱·템포) | 거리 |
| 요청문 → 태그 + 목표 숫자 | GPT | 사용자가 원하는 것 | — |

### 소리 숫자 — ReccoBeats
- 키 없음. iTunes 30초 미리듣기 파일을 `POST https://api.reccobeats.com/v1/analysis/audio-features` (multipart `audioFile`)로 올리면
  acousticness·danceability·energy·instrumentalness·liveness·loudness·speechiness·tempo·valence 를 준다(예전 스포티파이 오디오 특징과 같은 이름).
- 9/28 확인:

  | 곡 | energy | valence | danceability | acousticness | tempo |
  |---|---|---|---|---|---|
  | 아이유 밤편지 | 0.19 | 0.27 | 0.54 | 0.87 | 92 |
  | NewJeans Hype Boy | 0.88 | 0.61 | 0.62 | 0.19 | 94 |
  | 르세라핌 ANTIFRAGILE | 0.81 | 0.70 | 0.83 | 0.25 | 98 |

- 비공식 무료 서비스 — 한도·약관 모름. **곡당 한 번 부르고 DB 에 영구 저장**. 막히면 essentia.js(Node·윈도우 가능, ffmpeg 로 m4a 디코딩 필요, 2022 이후 업데이트 없음).
- 다른 후보: Essentia 파이썬(윈도우 pip 불가 → WSL/Docker), Cyanite.ai(상용·유료), CLAP(HF·Replicate, 유료·한도). Spotify 오디오 특징은 새 앱에 막힘, AcousticBrainz 는 종료.
- 한계: 30초 미리듣기는 보통 후렴이라 조용히 시작해 터지는 곡은 세게 나올 수 있다.

### 가사 — LRCLIB
- 키 없음. `GET https://lrclib.net/api/search?track_name=&artist_name=`. 9/28 DB 에서 무작위 15곡 중 **12곡(80%)** 가사 있음.
- GPT 가 가사 + 제목 + 가수를 읽고 **정해 둔 태그 목록 안에서** 주제 태그를 고른다. 가사가 없으면 제목·가수만으로.
- **가사 원문은 저장·화면 표시 안 함**(저작권). 태그만 남긴다.
- 오매칭(같은 제목 다른 곡)은 곡 길이 비교로 거른다.
- 가사와 소리가 반대인 곡이 많다(신나는 반주 + 슬픈 가사) → 뜻과 분위기를 **따로 점수 내서 합친다**. 하나로 뭉치면 서로 지운다.

## 4. 점수

- **뜻 점수** = 요청 태그 ↔ 곡 태그(Last.fm + 가사 주제) 코사인. 태그 개수에 휘둘리지 않고 겹침 정도를 본다.
- **분위기 점수** = 1 − (요청이 지정한 축들의 평균 거리). GPT 가 요청문에서 목표 숫자를 뽑는다
  (예: "집에 가고싶어요" → `energy 0.2, valence 0.35, acousticness 0.7`). 말하지 않은 축은 계산에서 뺀다. ±0.1 안쪽은 차이 없음으로 본다(GPT 숫자는 대충의 감).
  - 숫자를 태그로 바꿔(에너지 낮음 → mellow) 코사인에 넣지 않는다 — 경계에서 뭉개지고, 코사인은 크기를 무시해 0.2·0.2 와 0.8·0.8 을 같다고 본다.
- **최종** = a × 뜻 + b × 분위기. 소리 숫자가 없는 곡은 뜻만. a·b 는 반반에서 시작해 몇 문장 넣어 보고 조정.

## 5. 요청 해석 — GPT

- 출력 형식을 묶는다: 태그는 **DB 에 실제 있는 태그 목록** enum 안에서만, 목표 숫자는 0~1 선택값. 곡은 지어내지 않는다.
- 온도 0·모델 고정·요청문 정규화 후 해시 캐시 — 같은 문장이면 같은 결과.
- `.env` 에 `OPENAI_API_KEY` 필요. 모델은 정해야 함.

## 6. 순서

1. ReccoBeats 배치 — Track 에 소리 숫자 칸 추가, 밤 배치에서 없는 곡만. 키 없이 바로 가능
2. GPT 요청 해석 (태그 + 목표 숫자) — `recommend/interpret.ts` 몸통 교체
3. 점수 합치기 (뜻 코사인 + 분위기 거리)
4. GPT 곡 태깅 + LRCLIB 가사 — iTunes 장르 대체
5. (나중) 서랍 기록을 점수에 섞기
