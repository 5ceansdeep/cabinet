# 모바일 대응 계획 (보류 — 목업 완성 후)

결론: **가능하다. 구조를 갈아엎을 일은 없고, 3D 카메라와 입력 방식만 손보면 된다.**
지금은 목업을 데스크톱 기준으로 완성하는 중이라 착수하지 않는다. 착수할 때 아래 순서대로 한다.

## 1단계 — "폰에서 보고 만질 수는 있다" (반나절 분량)

| # | 할 일 | 지금 상태 | 손볼 곳 |
|---|---|---|---|
| 1 | 뷰포트 설정 | 없음 → 폰에서 화면이 축소돼 보일 수 있다 | `app/layout.tsx` 에 `export const viewport` 추가 |
| 2 | 화면 높이 단위 | `h-screen`(100vh) — 주소창이 접히면 아래가 잘린다 | `dvh` 로 교체 (`AuthFlow`, `Results`, `ArchiveRoom`) |
| 3 | 터치 제스처 충돌 | 디스크를 끌거나 꾹 누르면 스크롤·확대·길게눌러 메뉴가 끼어든다 | 캔버스에 `touch-action: none`, `-webkit-touch-callout: none`, `user-select: none` |
| 4 | 카메라 화각 | 세로 기준 고정이라 세로 화면에서 좌우가 잘린다 | 화면 비율이 1 미만이면 카메라를 뒤로 — `dimensions.ts` 의 `CAMERA` 를 aspect 로 보정 |
| 5 | 성능 단계 | 그림자 1024, 폴더 160개, dpr 1.5 고정 | 작은 화면이면 그림자 512·폴더 60개·dpr 1 |

## 2단계 — "폰에 맞게 쓴다"

- **탭 기반 안내**: 터치에는 호버가 없다. "마우스를 올리면" 식 문구를 탭 기준으로 바꾸고, 서랍을 탭으로 여는 흐름을 명시한다(대사는 `lines.ts` 에서 분기).
- **작은 화면 레이아웃**: 자막 줄 수 상한(3줄 → 2줄), 입력칸·네임택 가로 상한(`min(40vh, 80vw)`), 버튼 터치 영역 44px 이상.
- **가로 모드**: 가로로 눕히면 자막이 화면을 덮는다. 자막 위치를 세로 비율에 따라 조절.
- **결과 화면 조작**: 던지기(플릭)와 꾹 누르기가 터치에서 겹치지 않게 임계값을 따로 잡는다.

## 소리 — 웹에서 못 넘는 벽

- 첫 탭 전에는 브라우저가 소리를 막는다 → 이미 안내 문구로 처리했다.
- **아이폰은 무음 스위치가 켜져 있으면 탭을 해도 소리가 나지 않는다.** 웹에서 우회할 수 없다.
  안내 문구에 "무음 모드는 꺼 주게" 한 줄을 덧붙이는 정도가 최선이다.

## 건드리지 않아도 되는 것

- 편지(`/search`)·보고서(`/report/[id]`) 는 평범한 DOM 화면이라 여백만 줄이면 된다.
- 자막·입력칸·네임택은 화면 높이(vh) 기준이라 세로 화면에서도 비율이 유지된다. 가로 상한만 걸면 된다.
