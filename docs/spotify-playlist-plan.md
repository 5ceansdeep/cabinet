# 스포티파이 연동 — 플레이리스트 만들기 / 믹싱 / 곡 빼기

결론부터: **플레이리스트 생성은 된다. 진짜 "믹싱"(크로스페이드·비트매칭)은 안 된다. 스포티파이 로그인을 강제할 필요는 없다.**
그리고 **개발 모드 앱은 사용자 5명까지**라서, 심사를 통과하지 못하는 한 이 기능은 "데모용"이다. 이게 제일 큰 제약이다.

## 1. 되는 것

| 기능 | 가능 | 방법 |
|---|---|---|
| 곡을 스포티파이에서 찾기 | O | `GET /v1/search` — 제목+아티스트로 트랙 URI 얻기 |
| 플레이리스트 만들기 | O | `POST /v1/users/{id}/playlists` + `POST /v1/playlists/{id}/tracks` |
| 위로 슬라이드해서 곡 빼기 | O | 순수 프론트. 스포티파이와 무관 |
| 순서 바꾸기 | O | 보낼 때 순서대로 넣으면 됨 |
| 30초 미리듣기 재생·믹싱 | O | 단, 스포티파이 말고 iTunes Search API 의 미리듣기 mp3 사용 |

필요 권한(스코프): `playlist-modify-private` (비공개 플레이리스트), 공개로 만들려면 `playlist-modify-public`.

## 2. 안 되는 것

**진짜 믹싱은 불가능.**
- 전곡 재생은 Web Playback SDK 로만 가능하고, 이건 **듣는 사람이 프리미엄**이어야 한다. 무료 계정은 아예 안 나온다.
- SDK 오디오는 DRM 이 걸려 있어 소리 데이터를 건드릴 수 없다. 크로스페이드, 템포 맞추기, 음량 조절 전부 불가. 할 수 있는 건 다음 곡 큐에 넣기 / 건너뛰기 정도.
- SDK 는 서면 승인 없이 상업적 사용 금지.

**그래서 믹싱을 하려면 30초 미리듣기로 한다.**
- iTunes Search API: 키 없이 무료, 30초 mp3 URL 을 준다. Web Audio 로 받아오면 크로스페이드·음량·이어붙이기 전부 자유롭다. (DRIFT 레포에서 이미 iTunes 를 쓰고 있다)
- 스포티파이 `preview_url` 은 2024-11-27 이후 신규 앱에서 막혔다. `audio-features`, `recommendations`, `audio-analysis` 도 같이 막혔다. 그래서 곡 특징은 예정대로 Last.fm 태그 + iTunes 로 간다.

**정리**: 웹에서 들려주며 섞는 건 30초 미리듣기로, 스포티파이는 "완성된 목록을 계정에 저장하는 출구"로 쓴다.

## 3. 제일 큰 제약 — 개발 모드 5명

- 개발 모드 앱은 **인증된 사용자 5명**까지만 쓸 수 있다. 대시보드 허용 목록에 계정을 하나씩 직접 추가해야 한다.
- **앱 주인이 프리미엄**이어야 개발 모드 앱이 동작한다.
- 확장 쿼터(무제한)는 법인 사업자 + 실제 운영 중인 서비스 + **월 사용자 25만 명** 이상이라야 신청 대상이다. 개인 프로젝트는 사실상 불가.

→ 발표·포트폴리오용으로는 충분하지만, 아무나 가입해 쓰는 서비스로는 못 연다. 문서·발표에 이 한계를 적어 두는 게 낫다.

## 4. 로그인은 스포티파이로 해야 하나 — 아니다

- 플레이리스트를 만들려면 **그 사람의 스포티파이 계정 권한**이 필요한 건 맞다. 하지만 그게 곧 "우리 서비스 로그인 = 스포티파이"일 필요는 없다.
- 세계관상으로도 서류함 신 컨셉인데 첫 화면이 스포티파이 로그인이면 몰입이 깨진다. 스포티파이가 없는 사람은 아예 못 들어오게 된다.
- **권장: 지금 로그인은 그대로 두고, 스포티파이는 "연결"로.** 결과·믹스 화면에서 "스포티파이에 보내기"를 누를 때 처음 연결한다. 안 누르면 스포티파이 없이도 전부 쓸 수 있다.
- 방식: Authorization Code + PKCE. 토큰 갱신을 안전하게 하려면 백엔드(NestJS)에 붙이고, 액세스 토큰만 프론트로 준다.

## 5. 화면 흐름 제안

4번 결과 화면 뒤에 "믹스 편성" 단계를 둔다.

```
결과 디스크 캐러셀
  │  위로 슬라이드 → 그 곡 폐기 (서류 반려 느낌, "탁" 소리)
  │  남은 곡 = 편성
  ▼
믹스 편성 — 남은 곡 순서대로, 30초 미리듣기로 이어 재생(크로스페이드)
  │
  ▼ [스포티파이에 보내기]
  첫 클릭이면 스포티파이 연결 → 플레이리스트 생성 → 링크 보여주기
```

- 위로 슬라이드: 포인터 이벤트로 y 이동 추적, 일정 거리 넘으면 폐기. 되돌리기 한 번은 남겨 둔다(실수 방지).
- 스포티파이에서 곡을 못 찾는 경우가 생긴다(한국 인디는 특히). 못 찾은 곡은 빼고 만들되 "이 곡은 보관소에만 있다"고 알려 준다.
- 화면에 나오는 모든 문구는 [voice-persona.md](voice-persona.md) 말투("자네")를 따른다.

## 6. 단계

1. **스포티파이 없이 먼저.** 위로 슬라이드 폐기 + 믹스 편성 화면 + iTunes 미리듣기 크로스페이드. 여기까지는 제약이 하나도 없다.
2. **연결.** 백엔드에 OAuth(PKCE) 붙이고 "스포티파이에 보내기" 구현. 개발자 대시보드에서 앱 등록, 테스트 계정 허용 목록에 추가.
3. **못 찾은 곡 처리**, 만든 플레이리스트 목록 보관(5번 아카이빙과 연결).

## 7. 대안 — 유튜브 플레이리스트

된다. 그리고 "사용자 5명" 제약이 없다는 게 스포티파이보다 훨씬 낫다.

**되는 것**
- 플레이리스트 생성·곡 추가: `playlists.insert` + `playlistItems.insert` (OAuth, `youtube` 또는 `youtube.force-ssl` 스코프).
- 재생: IFrame Player API. **프리미엄 필요 없음.** 누구나 들을 수 있다 (스포티파이는 프리미엄 필수).
- 곡 찾기: `search.list` 로 제목+아티스트 검색.

**제약**
- **하루 검색 100번.** 기본 할당이 `search.list` 100회 + 나머지 전부 합쳐 10,000 유닛/일. 플레이리스트 생성 50, 곡 추가 1곡당 50 유닛이라 쓰기 쪽은 넉넉한데, **검색이 병목**이다. → 한 번 찾은 "곡 ↔ 영상 ID"는 반드시 DB/파일에 캐시해 두고 다시 검색하지 않는다. 곡 목록이 고정이면 미리 한 번만 돌려서 매핑을 저장해 두면 된다.
- 할당량을 늘리려면 감사(Audit) 양식을 제출해 ToS 준수를 심사받아야 한다.
- **플레이어를 숨길 수 없다.** 최소 200×200px, 절반 이상 화면에 보여야 자동 재생 가능, 플레이어 위에 다른 요소를 덮을 수 없다. 즉 "소리만 쓰는 배경 재생"은 규정 위반.
- **동시 자동 재생 금지** — 한 페이지에 자동 재생되는 플레이어는 하나뿐. 두 개를 겹쳐 크로스페이드하는 건 규정 위반이다.
- 공식 음원이 아닌 영상(커버·다른 버전)이 잡힐 수 있다. `Provided to YouTube by` 계열(토픽 채널) 우선으로 고르는 후처리가 필요하다.

**그래서 결론**
- 크로스페이드 믹싱은 유튜브로도 못 한다 → 믹싱은 그대로 iTunes 30초 미리듣기로.
- 결과물 내보내기는 **유튜브가 1순위**(아무나 씀), 스포티파이는 있으면 좋은 선택지(5명 한도).
- 디스크 더블클릭 미리듣기는 지금처럼 iTunes, "전곡 듣기"는 유튜브 플레이어를 화면에 보이게 띄우는 식으로 나눈다.
