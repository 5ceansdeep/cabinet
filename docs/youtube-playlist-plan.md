# 유튜브 재생목록 만들기 — 할당량을 최대한 아끼는 설계

결론: **미리듣기는 iTunes, 재생목록은 유튜브.** 유튜브 API 의 병목은 검색(`search.list`, 100 단위)이므로
**곡↔영상 짝을 미리 DB 에 쌓아 두고**, 재생목록을 만들 때는 검색을 한 번도 부르지 않는다.
로그인조차 없이 재생목록을 넘기는 길(무할당량)도 있어 두 가지를 같이 둔다.

(이 문서가 `spotify-playlist-plan.md` 를 대체한다. 스포티파이는 개발 모드 5명 제한 때문에 접었다.)

## 1. 역할 나누기

| 하는 일 | 쓰는 것 | 비용 |
|---|---|---|
| 30초 미리듣기 | iTunes Search API (`previewUrl`, m4a) | 무료·키 없음 |
| 앨범 커버 | iTunes `artworkUrl100` → `600x600` 치환 | 무료 |
| 곡 특징(태그) | Last.fm `track.getTopTags` | 무료 키 |
| 재생목록 만들기 | YouTube Data API v3 (OAuth) | 할당량 소모 |
| 곡 ↔ 영상 짝짓기 | 미리 쌓아 둔 DB (아래 3장) | 거의 0 |

> iTunes 는 `country=kr` 로 결과가 0건인 망이 있었다(로컬 이슈). `country=us` 폴백을 둔다.

## 2. 할당량 계산 (하루 10,000 단위)

| 호출 | 비용 | 언제 |
|---|---|---|
| `search.list` | **100** | 영상 ID 를 모를 때만 — 여기서 다 깎인다 |
| `playlists.insert` | 50 | 재생목록 1개 |
| `playlistItems.insert` | 50 | **곡 1개당** (묶음 삽입 API 없음) |
| `videos.list` | 1 | 영상이 살아 있는지·임베드 가능한지 확인 |

- 영상 ID 를 이미 알 때 10곡짜리 한 개 = 50 + 10×50 = **550 단위** → 하루 약 18개.
- 검색까지 하면 10곡에 1,000 단위가 더 붙어 1,550 단위 → 하루 6개.
- 즉 **검색을 없애면 하루 처리량이 3배**가 된다. 그래서 3장의 사전 적재가 핵심이다.

## 3. 곡 ↔ 영상 짝을 미리 쌓기 (배치)

`track_video` 테이블: `track_id, video_id, source, checked_at, embeddable`.
한 번 찾은 짝은 영구 재사용한다. 채우는 순서는 싼 것부터:

1. **MusicBrainz** (무료, 키 없음, 초당 1회, User-Agent 필수)
   - 곡 → recording → URL 관계(`streaming`, `free streaming`)에 유튜브 링크가 붙어 있는 경우가 많다.
   - 유튜브 할당량 0. 야간 배치로 천천히 돌린다.
2. **유튜브 검색 폴백** (`search.list`, 100 단위)
   - 1번으로 못 찾은 곡만. 하루 상한을 정해 큐로 처리한다(예: 하루 60곡 = 6,000 단위).
   - 질의는 `"{artist} - {title}"`, `videoCategoryId=10`(음악), 공식 음원(`Topic` 채널·Provided to YouTube by) 우선.
3. **수동 보정**: 인기 곡 몇백 개는 한 번 직접 채워 두면 대부분의 요청을 덮는다.

> 유튜브 페이지를 직접 긁는 크롤링은 이용약관 위반이다. 위 1·2번(공식 API·MusicBrainz)으로 대체한다.
> 시간이 지나면 영상이 내려가므로 `videos.list`(1 단위)로 주기 점검하고, 죽은 영상만 다시 찾는다.

## 4. 재생목록을 넘기는 두 가지 길

### A. 링크만 넘기기 — 할당량 0, 로그인 없음 (기본값 추천)

```
https://www.youtube.com/watch_videos?video_ids=ID1,ID2,...   (최대 50개)
```

- 유튜브가 임시 재생목록으로 열어 준다. 사용자가 "저장"을 누르면 자기 계정에 남는다.
- 우리 쪽 비용·로그인·심사 전부 0. 대신 **문서화되지 않은 주소**라 언젠가 막힐 수 있고, 제목을 정해 줄 수 없다.
- 그래서 "일단 들어보기"용으로 쓰고, 이름 붙여 저장하려는 사람에게만 B 를 권한다.

### B. 계정에 진짜로 만들기 — OAuth + API

흐름: **재생목록 만들기 누름 → (우리 서랍에 저장) → 구글 로그인 → 유튜브에 생성 → 링크 보여주기**

1. `playlists.insert` 로 비공개 재생목록 생성(제목 = 서랍 네임택, 설명 = 요청문 인용).
2. 곡 순서대로 `playlistItems.insert`.
3. 실패한 곡은 건너뛰고 "N곡 중 M곡 담김"으로 알린다.

- 스코프: `https://www.googleapis.com/auth/youtube` (또는 `youtube.force-ssl`). 토큰은 백엔드에만 둔다.
- **심사 전에는 테스트 사용자만** 로그인할 수 있다(구글 OAuth 테스트 모드). 심사를 받으면 풀린다.
- 할당량이 바닥나면 A 로 자동 폴백하고 "오늘은 링크로 드리지" 식으로 안내한다.

## 5. 아끼는 규칙 정리

- 재생목록 생성 시점에 **검색을 절대 부르지 않는다**(사전 적재 or A 방식).
- 곡↔영상 짝, iTunes 미리듣기 URL, Last.fm 태그는 전부 DB 캐시. 재호출 금지.
- 같은 사용자가 같은 목록을 다시 저장하면 기존 재생목록을 재사용(`playlists.list`, 1 단위)한다.
- 하루 사용량을 기록해 두고 80% 를 넘으면 B 를 잠그고 A 만 보여 준다.
- 정말 더 필요하면 구글에 할당량 증액을 신청한다(심사 있음).

## 6. 프론트 흐름 (목업 기준)

1. 결과 화면에서 남길 곡을 고른다(위로 던져 빼기).
2. `서랍에 넣기` → 디스크가 서랍으로 들어가고 네임택에 이름이 찍힌다(이미 구현).
3. 서랍이 닫힌 뒤 `유튜브 재생목록 만들기` 버튼 → 구글 로그인 → 완료되면 재생목록 링크.
4. 로그인을 원치 않으면 `유튜브에서 이어 듣기`(A 방식 링크).
