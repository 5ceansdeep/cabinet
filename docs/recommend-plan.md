# 추천 설계 — 거르기(임베딩 + 소리 숫자) → 고르기(Gemini 재정렬)

2026-09-30 개정. 9/28 안(태그 목록 + 코사인)을 버리고 **두 단계**로 간다.
1단계는 적은 재료로 후보를 거칠게 거르고, 2단계에서 Gemini 가 곡 설명을 읽고 미묘한 차이를 가른다.

## 1. 지금 문제

- **요청 해석이 낱말 사전.** 사전에 없는 말은 전부 기본값(`korean · indie · mellow`)으로 떨어진다.
  "안녕하세요"와 "집에 가고싶어요"가 같은 결과를 낸다.
- **곡 태그에 뜻이 없다.** 9/30 DB 88곡, 서로 다른 태그 167개 — 대부분 장르(k-pop 54곡)·정체(female vocalists, jyp entertainment, iu)·쓰레기
  (`under 2000 listeners`). 분위기·상황 태그는 거의 없고, 93개 태그는 한 곡에만 붙어 있다.
- **장르는 느낌을 못 가른다.** 같은 k-pop 안에 Hype Boy(energy 0.88)와 발라드(0.1)가 같이 있다.
- **곡 이름 표기가 섞였다.** 가수는 MusicBrainz 로 맞췄다(9/28, `catalog/musicbrainz.ts`). 제목(잔나비 "A Thought on an Autumn Night")은 아직.

## 2. 버린 안과 이유

- **태그 목록(감정·상황 40개)** — 요청이 `귀가` 로 해석되느냐 `혼자` 로 해석되느냐에 따라 결과가 통째로 갈린다.
  말을 조금만 바꿔도 튄다. 목록 관리도 끝이 없다("후련함" 다음엔 "씁쓸한 후련함").
- **장르 태그** — 위 1장. 점수에서 뺀다.
- **공식 곡 소개문 수집** — Last.fm 곡 소개는 무작위 20곡 중 **1곡**(9/30 확인, 그마저 발매 정보). 멜론·지니는 API 없음·약관,
  Apple 에디터 노트는 유료 계정·큰 발매작만, 나무위키는 비영리 라이선스. 무엇보다 "어떤 기분·상황의 곡인가"가 안 적혀 있다.
- **재료 늘리기로 미묘한 차이 잡기** — 숫자 칸을 늘리면 오차도 늘고 맞출 가중치도 늘어난다. 미묘한 차이는 읽고 판단하는 쪽(2단계)이 맡는다.

## 3. 구조

```
[곡마다 한 번 — 배치, 결과 영구 저장]
  제목·가수 + LRCLIB 가사 + 소리 숫자 (+ 있으면 Last.fm 태그·소개는 참고로만)
    ──Gemini(좋은 모델)──▶ 곡 설명 (정해진 틀)
    ──임베딩──▶ 벡터

[요청마다]
  요청문 ──Gemini(싼 모델)──▶ "이런 곡이면 좋겠다" 설명 + 목표 에너지·밝기
         ──임베딩──▶ 벡터

  1단계 거르기   전체 곡 → 20~30곡     뜻(벡터 코사인) + 소리(에너지·밝기 거리)
  2단계 고르기   20~30곡 → 순위        Gemini 가 요청문과 후보들의 곡 설명을 읽고 순위 + 곡마다 "왜 맞나" 한 줄
```

거르기 → 재정렬은 검색 서비스의 표준 구조. 1단계는 빠르고 거칠게(확실히 틀린 곡 버리기), 2단계는 느리고 섬세하게.

## 4. 재료 — 딱 셋

| 재료 | 보는 것 | 출처 |
|---|---|---|
| **뜻** | 가사·제목이 말하는 상황·감정 | LRCLIB 가사 + 제목 → Gemini 곡 설명 → 임베딩 |
| **에너지** | 조용한 ↔ 격한 | ReccoBeats `energy` |
| **밝기** | 슬픈 ↔ 밝은 | ReccoBeats `valence` |

- 에너지 × 밝기 = 심리학의 감정 두 축(각성 × 쾌-불쾌). 소리는 이 둘로 충분하다.
- 나머지 소리 숫자는 겹친다 (9/30, 86곡 상관):

  | 짝 | 상관 |
  |---|---|
  | energy ↔ acousticness | −0.86 |
  | valence ↔ danceability | 0.77 |
  | tempo ↔ 나머지 | 약함, 게다가 두 배로 잡히는 곡이 있다(Gee 179, 데이식스 190) |

- 빼는 것: Last.fm 태그·iTunes 장르(`genres.ts`)·danceability·acousticness·tempo. **DB 엔 남긴다** — 평가 세트(7장)로 다시 넣어 봐서 오르면 넣는다.

### 소리 숫자 — ReccoBeats (9/30 완료)
- 키 없음. iTunes 30초 미리듣기를 `POST https://api.reccobeats.com/v1/analysis/audio-features`(multipart `audioFile`)에 올린다.
- `catalog/sound.ts`, 매일 새벽 5시 + `POST /catalog/sound`(관리자). 86곡 전부(실패 0), energy 0.08(에일리 첫눈처럼)~0.92(데이식스).
- 비공식 무료 서비스 — 한도·약관 모름. 곡당 한 번, 영구 저장. 막히면 essentia.js(ffmpeg 로 m4a 디코딩 필요).
- 회사망은 IPv6 가 막혀 연결이 10초 걸려 끊겼다 — `main.ts` 에서 DNS 를 IPv4 먼저.
- 한계: 30초 미리듣기는 보통 후렴이라 조용히 시작해 터지는 곡은 세게 나온다.

### 가사 — LRCLIB
- 키 없음. `GET https://lrclib.net/api/search?track_name=&artist_name=`. 9/28 무작위 15곡 중 **12곡(80%)** 있음.
- **원문은 저장·화면 표시 안 함**(저작권). 곡 설명을 만드는 데만 쓴다.
- 오매칭(같은 제목 다른 곡)은 곡 길이(iTunes 와 LRCLIB `duration`) 비교로 거른다 — 틀린 가사면 설명이 통째로 틀린다.
- 가사가 없는 곡(20%)은 제목·가수만으로 설명 → 뜻이 약하니 1단계에서 소리 비중을 높인다.

## 5. 곡 설명 — Gemini (곡당 한 번)

- 곡당 한 번이라 **좋은 모델**을 써도 총비용이 작다. 요청 쪽은 매번이라 싼 모델.
- 정해진 틀로 쓴다 — 곡끼리 같은 말투여야 벡터 비교가 공평하다:
  ```
  감정: 이별 뒤의 후련함, 약간의 씁쓸함
  상황: 혼자 걷는 밤, 정리하는 시기
  가사: 떠난 사람을 원망하지 않고 보내 준다
  소리: 잔잔하게 시작해 후렴에서 트인다
  ```
- 설명 문장은 DB 에 남긴다 — 2단계 Gemini 가 읽을 재료이자, 보고서 화면에 "왜 이 곡인지" 보여 줄 재료.
- (평가 뒤 검토) 감정·상황·가사를 따로 임베딩해 요청과 가장 가까운 관점으로 재기 — 한 문장에 섞으면 뜻이 흐려질 수 있다.

## 6. 요청마다

- **풀어 쓰기**: 요청문을 바로 임베딩하지 않고 Gemini 가 곡 설명과 같은 틀로 "이런 곡이면 좋겠다"를 쓴다(같은 말투끼리 비교해야 잘 맞는다).
  목표 에너지·밝기(0~1)도 같이 — 말하지 않은 축은 비운다. ±0.1 안쪽은 차이 없음으로 본다(Gemini 숫자는 대충의 감).
- **1단계 점수** = a × 뜻(코사인) + (1 − a) × 소리(1 − 에너지·밝기 평균 거리). 소리 숫자가 없는 곡·목표를 안 말한 요청은 뜻만.
  맞출 숫자는 `a` 하나 — 평가 세트로 고른다. 후보는 넉넉히 20~30곡(여기서 버린 곡은 2단계가 못 살린다).
- **2단계** = Gemini 가 요청문 + 후보 곡 설명을 읽고 순위 + 곡마다 한 줄 이유. 곡은 후보 안에서만 고른다(지어내지 않는다).
- 같은 문장이면 같은 결과: 온도 0·모델 고정·요청문 정규화 후 해시 캐시.
- 기존 `seen`(몇 곡 더)·`thrown`(던진 곡 쪽에서 멀어지기)은 벡터로 옮긴다 — 던진 곡 벡터에서 먼 쪽을 올린다.
- 비용·속도: 요청마다 Gemini 두 번(풀어 쓰기, 재정렬) + 임베딩 한 번. 둘을 한 번으로 합칠지는 평가 뒤 결정.
- 벡터는 곡 수천 개까지 DB 에 JSON 으로 두고 코드에서 계산. 더 많아지면 Neon pgvector.

## 7. 평가 세트

바꿀 때마다 좋아졌는지 재는 기준. 없으면 느낌으로만 판단하게 된다.
- 요청 30개 + 요청마다 "나와야 할 곡"(곡 풀 안에서). 초안은 Claude 가, 확정은 사용자가.
- 상위 5곡 안에 기대 곡이 몇 개 들었나로 점수. `a`·후보 수·재정렬 유무·모델을 이걸로 고른다.
- 미묘한 쌍을 꼭 넣는다: "헤어져서 후련해" / "헤어졌는데 아직 못 잊어", "혼자라 편해" / "혼자라 외로워".

## 8. 정확도에 가장 큰 것 — 곡 풀

88곡뿐이면 방법이 아무리 좋아도 맞는 곡이 풀에 없다. 곡 풀 넓히기 배치(`catalog/pool.ts`)를 계속 돌린다.

## 10. LLM — Gemini (9/30 GPT 에서 바꿈, 무료 한도)

- 학생 계정이라 무료 한도로 시작. `GEMINI_API_KEY`(aistudio.google.com). 호출은 전부 `catalog/gemini.ts`.
- 곡 설명 `gemini-3.8-flash` → 막히면 3.6-flash → 3.5-flash-lite. 요청 `gemini-3.5-flash-lite` → 3.8-flash. 임베딩 `gemini-embedding-2`(768차원로 자름).
- **무료 한도는 모델마다 하루 20번**(3.8-flash 확인), Pro 계열은 0. 하루 한도에 걸린 모델은 태평양 자정까지 빼고 다음 모델로.
  Flash 는 503(사람 몰림)이 잦아 돌아가며 다시 부른다. 대화 모델이 다 막히면 요청문을 그대로 임베딩해 뜻만으로.
- **요청마다 대화 모델 1번** → 무료로는 하루 수십 요청이 한계(같은 문장은 캐시). 실제 사용자에게 열 땐 유료로 — 무료 한도에선 보낸 글이 Google 모델 개선에 쓰일 수 있다.
- 첫 확인(9/30, 88곡): "안녕하세요"와 "집에 가고싶어요"가 이제 다른 결과. "신나게 춤추고 싶어" → 키키·르세라핌·Hype Boy·Gee,
  "헤어졌는데 아직 못 잊겠어" → The Day·잔나비·비와 당신. "헤어졌는데 후련해" 는 Lilac·사건의 지평선에 그냥 밝은 곡(IVE ELEVEN)이 섞인다 — 2단계 재정렬 몫.
- 점수가 86~93% 에 몰려 화면 일치도로는 차이가 안 보인다 — 코사인 범위가 좁아서. 표시용으로 늘려 보일지 정해야 함.

## 11. 첫 평가 (9/30, 88곡, Claude 초안 30개, 상위 5곡)

| 설정 | 하나라도 맞음 | 평균 재현율 |
|---|---|---|
| A 0.6, 평균 안 뺌 (처음) | 24/30 | 43% |
| A 1.0(뜻만), 평균 안 뺌 | 26/30 | 59% |
| **A 0.5 + 평균 빼기 (지금)** | **29/30** | **68%** |

- **허브 곡**: 곡 설명이 다들 "밤·혼자·아련함" 쪽이라 평균에 가까운 곡(경서 나의 X에게, 검정치마 Everything, 성시경 너의 모든 순간)이
  어느 요청에나 끼었다. 곡 풀 평균 벡터를 요청·곡 양쪽에서 빼고 다시 길이 1 로(`score.ts` centerer) — 공통 성분을 지우고 곡마다 다른 것만 비교.
- 평균을 안 빼면 소리 숫자를 섞을수록 나빠졌다(허브가 가렸다). 빼고 나니 반반(0.5)이 뜻만(61%)보다 낫다.
- 남은 약점: "세상에 우리 둘만 남은 것 같아"(0/3), "혼자라 외로워"(1/4 — Love Poem·Everything 이 먼저). 곡 설명에 "밤"이 거의 다 들어가는 Gemini 버릇도 손볼 거리.
- 주의: 세트가 작고 Claude 가 곡 설명을 보고 기대 곡을 골라서 후하게 나온다. 사용자가 세트를 고친 뒤 다시 잰다.
- 9/30 세트 넓힘: 39개(88곡 전부 한 번 이상, 새 쌍 "설레는 끌림 / 위험한 끌림"·"끝난 사랑 정리 / 식어 가는 사랑") → 평균 빼기 + A 0.5 가 **38/39·65%**(0.8 은 37/39·66%). A 는 0.5 유지.
  "위험한 사람인 거 아는데 끌려" → LOVE DIVE·Rose 1·2등, "확 끌려" → The Feels·Hype Boy — 쌍이 갈린다.

## 12. 2단계 재정렬 + 신의 한마디 (9/30)

- 한 번의 Gemini 호출(`MODELS.rerank`, 3.8-flash 부터)로 후보 20곡을 번호로 받아 순위, 곡마다 한 줄 이유, 신의 한마디(`line.ko` 자막 / `line.en` 음성)를 받는다.
  이상한 번호는 버리고 빠진 후보는 1단계 순서로 뒤에. 실패하면 1단계 순서 그대로·한마디 없이.
- 화면: 한마디는 프레임 아래 자막 띠, 이유는 가운데 디스크 이름표 밑. 일치도 % 는 뽑힌 곡들 것을 큰 순서대로 새 순서에 나눠 준다(2등이 1등보다 높아 보이지 않게).
- 음성: 지금은 기계 음성이 한국어 자막을 읽는다. **ElevenLabs 를 붙이면** 백엔드가 `line.en` 을 ElevenLabs(스트리밍, with-timestamps 로 자막 시각)로 — 키는 백엔드에만.
- 평가(`npm run eval -- rerank`, 39개): 1단계만 38/39·65% → 재정렬 후 **35/39·59%** 로 점수는 내려갔다.
  다만 틀린 곡도 말이 되는 경우가 많다("못 잊겠어" → 첫눈처럼 너에게 가겠다·Star Star Star). 정답지를 1단계와 같은 곡 설명으로 만들어 1단계 쪽으로 기울었을 수 있다.
  **사용자가 정답지를 고친 뒤 다시 재서 재정렬 순서를 쓸지 정한다** — 안 쓰면 1단계 순서 + 한마디·이유만 받는다.
- 요청마다 Gemini 2번(풀어 쓰기 lite + 재정렬 3.8-flash) — 모델별 한도가 갈려 무료로 하루 받을 수 있는 요청은 오히려 는다.
